# 06. E1 再走査 — OTP 分類の環境差と再起動間の安定性

実験 E1(READ_FROM_OTP の全 index 走査、[docs/02](02_dat_encryption_model.md) §11)の再実施と比較検証の記録(2026-11-13 実施)。E1 は公式ユーザーランド環境での単一ブート測定で、「再起動を跨いだ分類の安定性」は E1 自身が残件として明記していた。また、現在の Debian 環境(6.12 系カーネル + 移植ドライバ)で同じ読み出しが同じ結果を返すか(ホスト環境差の影響)も未確認だった。本書では E1 と同一のツール・同一の手順で再走査し、この 2 点を切り分ける。

**到達点(要約)**:

- 3 測定(E1 = 公式 FW 環境、走査1 = Debian 環境のブート 1、走査2 = Debian 環境のブート 2 = 再起動後)は、**全 256 index で完全に一致**した。成否・ゼロ/非ゼロ分類とも不一致は 0 件で、分類ファイルはバイト単位で同一(SHA-256 も 3 者とも同一値)になった。
- これにより (a) READ_FROM_OTP の分類はホスト環境(公式 FW のドライバ/ユーザーランドか、Debian 環境のドライバか)に依存しないこと、(b) 今回の再起動(Debian → Debian)を跨いでも分類が変わらないこと、が実測で確定した。E1 の残件「再起動間の安定性」は、**分類(ゼロ/非ゼロ)の粒度では解消**した。
- 分解能の限界: nonzero の index については、応答値が変わってもゼロでない限り検出できない。「値そのものの安定性」は本測定では判定していない(§5)。zero 側(85 件)は「8 バイト全ゼロ」が値そのものなので、値レベルでも一致が言える。

## 1. 問い

1. **環境差**: E1 の測定は公式 FW のユーザーランド + 公式ドライバ経由だった。現在の Debian 環境(別カーネル・移植ドライバ)から同じコマンド列を発行した場合、返る分類は同じか。
2. **ブート間安定性**: 同じ環境でも、再起動を挟むと分類(特にゼロ/非ゼロの境界)が変わる index はあるか。E1 の実施範囲は単一ブート内のみで、これは未実施のまま残っていた。

## 2. 手順(E1 との同一性)

- **ツールは E1 のものを無変更で使用**した。バイナリの SHA-256 は E1 実施時の記録値と一致(`00e2b063…`)、ソースも同一(`c435acec…`)。Debian 環境でそのまま動作したため、再ビルドはしていない。
- index ごとの手続きは E1 および dtvtuner 自身の発行手続きと同一: ドライバ open → OPEN_GENERIC(RSA モード)→ READ_OTP(コマンド `0x116`、KeyIndex 0x00–0xFF)→ CLOSE_GENERIC → close。パケットレイアウトは [docs/02](02_dat_encryption_model.md) §11 のとおり。
- **読み取り専用であることの事前確認**: 実行前にソースを精読した。使用するシステムコールは open / close / ioctl / write(標準出力への分類行)/ exit のみ。発行するチップコマンドはセッション開設(OPEN_GENERIC)・読み出し(READ_FROM_OTP)・セッション閉鎖(CLOSE_GENERIC)だけで、書き込み系コマンドは含まれない。応答の生値は分類した直後にツール内でゼロ消去され、出力・保存される経路は無い(E1 と同じ設計)。sys1 / SPI への書込みも、`.dat` へのアクセスも無い。
- 実施環境:
  - **E1(基準)**: 公式 FW のユーザーランド環境、2026-11-12 実施([docs/02](02_dat_encryption_model.md) §11)。
  - **走査1**: 現在の Debian 環境(ブート 1)。通常サービス(チューナーサービス等)が稼働中の状態で実施。
  - **走査2**: 走査1 の後、実機を 1 回再起動(Debian → Debian)し、通常サービスの復帰を確認してから実施(ブート 2)。
- 全範囲の前にアンカー 4 点(0x00 は zero 側、0x0B / 0x40 / 0xFF は nonzero 側)を単発で読み、全て E1 の分類と一致することを確認してから全範囲を実施した。

## 3. 結果

| 測定 | 環境 | 集計 | 分類ファイル SHA-256 |
|---|---|---|---|
| E1 | 公式 FW ユーザーランド | ok=256、zero=85、nonzero=171、err=0 | `23be79df2df1ed3cd6883f8779b9ddccc3b5986495e66ceae0f5b104770b8031` |
| 走査1 | Debian 環境・ブート 1 | ok=256、zero=85、nonzero=171、err=0 | 同上(バイト単位で同一) |
| 走査2 | Debian 環境・ブート 2(再起動後) | ok=256、zero=85、nonzero=171、err=0 | 同上(バイト単位で同一) |

- 3 ファイルとも 257 行(分類行 256 + SUMMARY 1)で、バイト単位で同一。したがって **index ごとの不一致は 0 件** で、「不一致 index の列挙」は無しが結果である。
- 分布も当然に同一: zero は 0x00、0x03–0x04、0x06、0x08、0x0A、0x0D、0x31–0x3F(15 件)、0x43–0x81(63 件)の計 85 件。nonzero は残り 171 件(大きな連続塊は 0x82–0xFF の 126 件と 0x0E–0x30 の 35 件)。
- 分類ファイルの原本は手元の作業環境に保管した。本リポジトリには値だけでなく分類ファイル自体も含めていない(E1 以来、素材は作業側で管理する方針)。

## 4. 事実と解釈

### 4.1 観測事実

- 同一ツール・同一手順による 3 測定で、全 index の成否と分類が一致した(§3)。
- 環境の組: E1 と走査1 は「環境とブートの両方」が異なる組、走査1 と走査2 は「環境が同じでブートだけ」が異なる組である。

### 4.2 解釈

- **環境差は無い(分類粒度)**: E1 と走査1 の一致は、読み出し経路のホスト側(カーネル・ドライバ実装・ユーザーランド)が変わっても、返る分類が変わらないことを示す。分類はチップ側ストアの内容(のゼロ/非ゼロ分布)をそのまま反映しているという理解と整合する。
- **ブート間安定性あり(分類粒度)**: 走査1 と走査2 の一致は、ドライバ再初期化とチップ側ファームウェアの再ロードを含む再起動を跨いでも、分類レベルで動的に変わる index が無いことを示す。カウンタやセッション素材のような動的 index があれば、値がゼロ境界を跨いだ場合に分類の不一致として現れるはずだが、現れなかった(ゼロ境界を跨がない値変動は本測定では見えない。§5)。
- 2 つの問いは分離できている: 走査1 が「別環境・別ブート」で先に E1 と一致したため、走査2 との一致はブート差単独の証拠として読める。

### 4.3 本結果が変えないこと

- OTP 各 index の**意味論**は引き続き未確定([docs/04](04_open_questions.md) §2.2)。本書は「何が入っているか」ではなく「読みの分類が環境・ブートで変わらないか」だけを扱った。
- 録画経路と OTP の接続が無いという既存の判定([docs/02](02_dat_encryption_model.md) §10)にも影響しない。本再走査は E1 の測定自体の再現性・安定性を確定するためのもので、副線(鍵だけ抜いて PC で復号)の分岐条件を変えるものではない。

## 5. 分解能の限界と残件

- **値レベルの安定性は未測定**: nonzero の 171 件については、応答値が再起動で変わっていても分類が nonzero のままなら検出できない。値レベルまで見るには、応答値を保存せずハッシュだけを残すツール変種(分類 + 応答のハッシュを出力し、生値は破棄する)が要る。当初の実験設計には「安定性はその場のハッシュ比較で判定する」案があったが、実装されたツールは分類のみであり、本再走査は手順同一性を優先して同じツールを使った。値レベルの安定性確認は、変種ツールの作成を含めて残件とする。**→ 追記(2026-11-13): この残件は [docs/07](07_otp_value_level_stability.md) で実施した。結果は一様ではなく、0x00–0x81 と 0xFF は値レベルでも固定、0x82–0xFE は読み出しごとに値が変わる揮発域だった。**
- **サンプル範囲**: 環境 2 種・ブート 3 回分の測定である。電源断を伴うコールドブートや、公式 FW 環境での再起動跨ぎは今回の範囲外。
- 意味論の特定は [docs/04](04_open_questions.md) §6 の次段項目として残る。
